# 原音对照方法

## 数据流

媒体 → 保留时间轴的单声道 WAV → TransKun 与 ByteDance 独立识别 → 原音频谱复核分歧 → 可选视频音条支持 → 演奏事件 → 两条输出支路：

- 演奏：实际起止时间 + 踏板 + 有限力度校准 → MIDI 与采样钢琴重奏 MP3。
- 阅读：分手、分声部、节拍网格、合理记谱时长、延音线 → MusicXML 与 PDF。

禁止用阅读谱的量化时间反过来覆盖演奏时间。处理不会增加“让音乐丰富”的无证据和声。

## 原音与模型

FFmpeg 以 22050 Hz / 单声道 / 16 bit 提取；保留媒体开头的相对延迟和音频缺口。TransKun 输入重采样到模型配置的 44100 Hz，ByteDance 到 16000 Hz。时间基准是媒体开始后的相对秒，元信息保留原始起始 PTS。提取音符后的前导空白可裁去，记录 `source_origin`。

模型权重固定在 `assets/models/`；部署校验 `assets/checksums.json`。模型按顺序运行，避免同时占用显存。原始 MIDI、事件、踏板和 ByteDance 概率矩阵全部留在工作目录。

## 双模型与原音分歧筛选

- 同音高起音差 ≤65 ms 时一对一匹配；共同识别的事件先保留，但这不意味着已经人工确认。
- STFT：4096 点、110 采样 hop。起音前约 85–40 ms 与后 15–65 ms 的能量差用于估计新击打。
- 从本曲可靠候选构建音高谐波模板，避免仅靠通用频谱峰误识别高次谐波；用非负最小二乘比较加入／移除候选后解释原音的改善。
- 单模型候选若有低方 12/19/24/28/31/36 半音载体，要求独立源增益 ≥.035、相对系数 ≥.25、ByteDance 起音峰 ≥.20。
- 其他单模型候选：源增益 ≥.018、相对系数 ≥.18，且起音峰 ≥.16 或来自 TransKun；或起音、帧概率均 ≥.70。
- 45–220 ms 内同音高重复候选来自 TransKun，源增益 ≥.065、相对系数 ≥.35 时可恢复；未确认的单模型 <20 ms 事件排除。
- 每个保留／排除决定写入逐音审计。阈值是已验证流程的默认值，可按具体录音在新版本中调节。

## 视频音条复核

只有完整 A0–C8、88 键、近似水平且满宽的下落音条画面适用当前检测器。实拍视频、裁剪键盘、移调显示、其他键数不应直接开启。

先抽帧检查，将画面缩放到 **1088 × 612** 后测量击键线 `strike` 和键盘黑键采样行 `keyboard`。检测行自动设为 `strike - 230/-180/-130`，因此击键线须 ≥230。当前键中心默认满宽 88 键映射，不能推广到任意画面。

```json
{
  "vivalavida2": {"strike": 328, "keyboard": 380, "title": "Viva La Vida"},
  "perfect2": {"strike": 395, "keyboard": 447, "title": "Perfect"},
  "hesapirate1": {"strike": 302, "keyboard": 355, "title": "He's a Pirate"}
}
```

键名是输入文件的原始 stem。这些数值只对应本项目已检查过的三个视频；同名的新视频必须重新看帧。把 JSON 保存为配置后传入 `--visual-config /path/to/calibration.json`。

算法在 3 行跟踪彩色条，估计运动速度，用原音起音拟合时间偏移和漂移。至少 2 行一致、源起音支持 ≥.09 且存在模型候选，才恢复原先排除的音。运动相关 <.45 或无轨迹时禁用恢复，保留原因。不能因为有视频而把没有音频证据的弹幕、火花或残影补成音符。

源音频缺口目前只保留时间轴并从力度估计中屏蔽；此通用入口不凭视频独自重建缺失片段。若要复现 shivers 的特殊缺口修复，需先人工核查轨迹并单独记录视频独立补音。

## 力度、踏板与音色

基于源音和未校准采样重奏的 RMS 轮廓，550 ms 平滑、1 s 中值、600 ms 二次平滑，去除整体录音增益差，变化限于 ±4 dB、MIDI velocity 最多 ±12。音高、起音、松键和踏板均不因力度校准改变。

TransKun 的按键时长与 CC64 踏板独立处理。同音高下一次起音前结束旧 MIDI 按键；采样重奏允许自然声学尾音并在新击打后衰减旧尾声。采样使用多相重采样、力度亮度过滤和轻房间混响。MP3 母带目标约 -18 LUFS，限幅器前后过采样并检查真峰；不宣称复刻原钢琴音色。

## 记谱

按用户给定 BPM 先拟合源起音网格；无参数时估计速度先验。稳定节拍用固定脉冲，较自由的演奏用起音追踪；复合拍按附点四分音符追踪后转成四分音符单位。拍号与首小节起点仍需复核，当前不会识别任意变拍子／弱起／连音分组。

以 32 分音符单位整理阅读谱，分旋律、内声部、伴奏、低音；谱面延音可包含已测量的踏板支持，但不改 MIDI 按键时长。快速同键起音发生谱面碰撞时保留独立击打，记录阅读谱位移。

## 交付检查

要求模型和源文件哈希可追溯；MIDI 逐音核对音高、力度、左右手及起止误差（默认 <2 ms），检查同键重叠、卡音和踏板释放；MusicXML 逐声部比对音符及小节时值；PDF 非空并抽看首页和中段；MP3 完整解码、响度与真峰测量；源音包缺口、>300 ms 异常近静音、快速重复音统计；已有结果 SHA-256 未改变。

强制程序检查会阻止交付无效文件，连续性异常与谱面推定仍需审阅。RMS 相关性仅衡量粗力度轮廓，不能作为音高／节奏准确率，更不能写成“已听过，完美一致”。
